# corpus / benchmarks / prolog

The community-standard Prolog **performance** benchmark suite — the
*van Roy / Aquarius / Warren* set (UC Berkeley CS Report UCB/CSD 89/50,
Ralph Haygood / Peter Van Roy, 1989) — adapted for the SCRIP three-mode
Prolog backend (GOAL-PROLOG-BB).

Namespaced under `prolog/` so the benchmark root holds per-language sets
(`snobol4/`, `icon/`, `prolog/`), mirroring `corpus/programs/<lang>/`.

> These are **performance** benchmarks (the classic timing suite). They are
> distinct from the GNU Prolog **conformance** tests (`t_arith`, `t_atom`, …)
> that `scripts/install_gnu_prolog_tests.sh` pulls into
> `corpus/programs/prolog/gnu_tests/`, and from the SCRIP **rung ladder**
> (`corpus/programs/prolog/rung*.pl`, GATE-3). This folder is the
> performance-and-coverage frontier driver.

## Provenance — two recognised upstreams (`src/`, pristine, unmodified)

Both descend from the same 1989 Berkeley suite; the two practical homes are
kept verbatim under `src/` with their upstream READMEs and calibration data:

| dir | upstream | what it is |
|-----|----------|-----------|
| `src/swi-vanroy/` | <https://github.com/SWI-Prolog/bench> | The canonical GitHub home of the "van Roy set". 37 programs, each providing `top/0`; `_programs_calibration.pl` carries the per-program iteration counts tuned to ~1 s on an AMD 3950X (SWI 8.5.2). |
| `src/gnu-examplespl/` | gprolog `examples/ExamplesPl/` (in the uploaded `4-gprolog-master.zip`) | The portable-`hook.pl` form: one `common.pl` driver + a per-system `HOOK.pl` (SWI, YAP, SICStus, Ciao, BinProlog, WAMCC, XSB) so the *same* sources run across every Prolog. `_PROGS` is the canonical 17-program list. |

The pristine `src/` trees are reference only — never run by the SCRIP gate.

## The runnable SCRIP set (`bench/`)

`bench/<name>.pl` is the **SCRIP-dialect** form of each benchmark: the same
core computation, but the non-deterministic *timing* harness (`do_bench`,
`get_cpu_time`) is replaced by a **deterministic result signature** — the
program runs the computation once and `write/1`s its answer, so any runner
can verify correctness without knowing variable names (same rule as
`benchmarks/snobol4`: the final output goes to stdout, not a variable). Each
uses the SCRIP driver convention `:- initialization(main). main :- …`.

### Artifacts side-by-side (the house convention)

Every `bench/<name>.pl` carries its artifacts beside it:

| file | meaning |
|------|---------|
| `<name>.pl` | SCRIP-dialect source |
| `<name>.expected` | ground-truth output, generated from the **gprolog oracle** (banner/compile noise stripped) |
| `<name>.s` | the mode-4 `--compile --target=x86` artifact — the **honest current** compiler output (regenerated by `util_regen_prolog_bench_s_artifacts.sh`), present **only** when codegen succeeds and the result assembles |
| `<name>.s.FENCED` | a one-line marker present **instead of** `.s` when the program is still rejected by `pl_gz_admit` (no codegen yet). When the PL-BB ladder admits that shape, regen replaces this marker with a real `.s`. |

The `.s` is never a pinned golden and `.s` byte-identity is never a gate
(per RULES.md): it tracks design churn. The *correctness* gate is
`<name>.expected`.

## Running

```bash
# SCRIP three-mode benchmark runner (m3 --run, m4 --compile x86, + oracle cross-check)
bash SCRIP/scripts/test_bench_prolog_modes.sh

# regenerate the side-by-side .s / .s.FENCED artifacts after any codegen change
bash SCRIP/scripts/util_regen_prolog_bench_s_artifacts.sh "<rung>"
```

`test_bench_prolog_modes.sh` reports, per benchmark: `m3` (PASS/FENCE/FAIL),
`m4` (PASS/FENCE/BUILD/NOEMIT/FAIL), the gprolog `ORACLE` cross-check, and a
summary `green / frontier(fenced) / broken / total`. **broken=0** is the
invariant; **fenced** is the live frontier the ladder is shrinking.

## The suite (canonical core + coverage extensions)

The classic core appearing in essentially every Prolog performance paper:
`boyer browse chat_parser crypt deriv nreverse qsort queens tak zebra reducer
meta_qsort nand sendmore poly_10`. Bottleneck per program:

| Program | Stresses |
|---------|----------|
| `nreverse` | list build + O(n²) deep recursion (the canonical WAM micro-bench) |
| `tak` | recursive integer arithmetic (`is/2`, `>`, `=<`), no structures |
| `qsort` | cut (`!`), multi-clause partition, structure-building recursion |
| `queens_8` | nondeterministic search, backtracking, list permutation |
| `crypt` | cryptarithmetic, arithmetic + generate-and-test |
| `deriv` | symbolic differentiation, structural recursion |
| `meta_qsort` | a meta-interpreter running qsort (clause/`call` indirection) |
| `boyer` | Boyer–Moore rewrite prover — large term rewriting |
| `browse` | property-list build + query over generated database |
| `zebra` | the zebra puzzle — pure logical-variable constraint via unification |
| `reducer` | a graph reducer (combinator evaluation) |
| `nand` | a nand-gate circuit synthesiser — the largest classic program |
| `chat_parser` | the CHAT-80 natural-language parser fragment (DCG-heavy) |
| `sendmore` | SEND+MORE=MONEY, arithmetic constraint search |
| `poly_10` | symbolic polynomial exponentiation |

Extensions from `src/swi-vanroy` widen coverage (arithmetic, indexing,
determinism): `fib log10 ops8 times10 divide10 query sieve serialise unify
perfect prover simple_analyzer flatten mu fast_mu`.

## Adding a benchmark

1. Pick the program from `src/swi-vanroy/` (or `src/gnu-examplespl/`).
2. Write the SCRIP-dialect `bench/<name>.pl`: `:- initialization(main).`
   plus `main :- <run-once>, write(Result), nl.` (no timing).
3. Generate the oracle: strip the gprolog chrome —
   `gprolog --consult-file <name>.pl --query-goal halt | grep -vE '^GNU Prolog|…' > <name>.expected`.
4. `bash SCRIP/scripts/util_regen_prolog_bench_s_artifacts.sh "<rung>"` to
   emit `<name>.s` (or `<name>.s.FENCED`).
5. Update this table; add the program under the PB-BENCH rung in
   `.github/GOAL-PROLOG-BB.md`.
