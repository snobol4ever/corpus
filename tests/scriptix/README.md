# tests/scriptix: the cross-language pairs

Lon's words of 2026-11-18, in the chairman's window: simple tests that define variables from one language and print them from another, and the same for functions with arguments and return values, a good combination of each of the seven languages with the other seven, as SCRIPtix and Jupyter/JSON files. The design is the cao's (`DESIGN.md` of its witness folder).

- `variables/` and `functions/`: two suites, 49 pairs each (SNOBOL4, Snocone, Rebus, Icon, Pascal, Prolog, Raku, each defining and each using). A pair is `A_to_B.md` (the SCRIPtix document), `A_to_B.ipynb` (the notebook of the same two cells) and its one answer, `A_to_B.out`, the file the files form reads; the index is `ALL.csv` and the chunks `PARTITION.tsv`.
- `make_pairs.py` is the one source: it writes every file above but `PARTITION.tsv`. No file of a set is edited by hand. `make_pairs.py --check` reads what stands beside it and writes nothing (rc 0 equal, rc 1 naming the first file that drifted); `make_pairs.py --out DIR` writes elsewhere. After a change, `util_suite_partition.py build ALL.csv` in each set.
- THE GRADE: the cycle grades each set as the suites `scriptix-variables` and `scriptix-functions`, an entry a pair, mode 3, the file road (`scrip A_to_B.md`, the `grader` cell empty: the plain text road). The REAL-KERNEL road, the one Lon's Lab takes (the notebook run by a Jupyter client that sends no cell metadata, so each code cell carries its language as a first line `%%Lang`), is the second road of the same entries and the suites `scriptix-variables@kernel` and `scriptix-functions@kernel`, mode 3, written by `test_scriptix_pairs_kernel_road.sh` (the harness), a pair measured only when its file road and its session-host road already read its answer. A pair that is red is a witness of the row that will cure it, never an exclusion.

- THE STRUCTURE SETS (the cao 2026-11-18, on Lon's one-storage word of 15:4x CST: DATA and record, ARRAY and list, TABLE and table stored identically): `records/`, `sequences/` and `tables/`, three more sets beside variables and functions, made by the same `make_pairs.py`. A pair is THREE cells: A makes the structure in its own form in a global (`ROOT`, `SEQ`, `TAB`), B declares it by its own form, reads it by its own subscript and makes one back (`BACK`), and A reads that. Records: a `tree(t,v,n,c)` of two children, by SNOBOL4, Snocone and Rebus DATA, the Icon record, the Pascal record type, the Raku class and the Prolog term; sequences: three elements, by the SNOBOL4 ARRAY, the Icon list, the Pascal array, the Raku Array held in a scalar and the Prolog list; tables: two keys, by the SNOBOL4 TABLE, the Icon table and the Raku Hash held in a scalar. PASCAL AND PROLOG HAVE NO TABLE, so `tables/` has 25 pairs (five languages) and the matrix prints `-` for each pair with a Pascal or Prolog end: never red. Each answer is derived by the generator from the rule (`records/` reads root plus 2, leaves 1 2, back times 2, back leaves 3 4), never cut from SCRIP, and the pairs that read red are witnesses of the causes the matrix names, never exclusions.
