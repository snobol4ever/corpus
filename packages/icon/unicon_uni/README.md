# unicon_uni

Unicon's `uni` tree (https://github.com/uniconproject/unicon; the GNU GPL for the extensions and the GNU LGPL for the class library, Unicon's
COPYING), read IN PLACE from `/home/resources/unicon/uni` (`ALL.source`); no file of it is stored here (CIO-96). This folder holds our index
(`ALL.csv`, the `path` cell is the path from the tree's root, the dialect cell unicon), each entry's answer `NAME.out` cut from the Unicon
translator (`unicon_bin`, each program translated inside a scratch copy of its own folder so the ucode the built tree ships beside it links), and
`ALL.omit`, which names every file that is no entry with its verdict. Built by
`harness/scripts/util_build_package_suite.py corpus/packages/icon/unicon_uni --lang icon --mine CENSUS.tsv` (2026-11-11, COO-516); the census is
`/home/resources/progress/MINING-UNICON-UNI-CENSUS.tsv`: 710 files, 15 ENTRY, 566 LIBRARY (no procedure main: classes and library modules),
54 NO-OUTPUT, 43 NEEDS-DISPLAY, 19 ORACLE-REFUSES, 6 NEEDS-NETWORK, 4 NEEDS-INPUT, 2 DIFFERS-BETWEEN-RUNS, 1 READS-THE-ENVIRONMENT.

An entry is a program unicon answers the same twice with standard input closed, inside 60 s, with something on standard output; it is graded on
standard output and exit status. The tree's text carries no statement-ending semicolons (Unicon inserts them at line ends) and SCRIP's Icon asks
for them, so a first reading is expected red on the parse; the conversion is the row mining-a-test-suite-from-unicon-uni's amendment CIO-101.

THE SEMICOLONED COPIES (senior_03, row unicon-uni-red-uflex-test-hello, 2026-11-12 CST; the layout is the harness's own: pkg_source_root reads a row's program from the package folder first and from the ALL.source root only when the package does not hold the file). A converted entry is a hand-semicoloned file stored HERE at its ALL.csv path (uflex/test/hello.icn beside uflex/test/hello.out), and an entry with no copy still reads the upstream text in place and reads red on the parse. The upstream tree under /home/resources/unicon/uni is never edited and never written beside (Lon: never touch an upstream repo). No tool adds the semicolons (skill unicon section 4); a copy is proved by unicon giving the same answer for the edited text as for the original (the entry's .out) and by SCRIP reading PASS. An entry that imports a package or links a library module needs that closure converted the same way, stored beside the entry under this folder and named to the harness by an ipath line of a CONTRACT.tsv (the unicon_tests package's uni_lib is the precedent); the closure is large for most entries (xml: 36 files, ulsp: 11, lang and util inside lib: about 80), so each entry is its own row. THE IPL PAIR (senior_08, row unicon-uni-red-progs-uget, 2026-11-12 CST): ipl/basename.icn and ipl/options.icn are hand-semicoloned copies of /home/resources/unicon/ipl/procs (not of the uni tree), named to the harness by the ipath line of this folder's CONTRACT.tsv; the original and the copy answer alike on a driver of 27 lines (options of every type, the @file form, --, the = strip form, the three errproc paths, basename with and without a suffix). They serve every entry that links basename or options (uget, jsvalid, ivibmigrate, ulsp/launch-lsp, xml/testxml). A closure already vendored semicolon-ready elsewhere in corpus is named, not copied twice: progs/genAcc imports lang, and the second ipath line of CONTRACT.tsv names ../unicon_tests/uni_lib, which holds all 14 lang files (officer_02, row unicon-uni-red-progs-genacc, 2026-11-12 CST). Corpus may host GPL test text because corpus never ships (Lon 2026-11-12 19:4x, skill suites-and-grading section 1); Unicon's COPYING is stored beside the copies. THE JSVALID CLOSURE (senior_08, row unicon-uni-red-progs-jsvalid, 2026-11-12 CST): progs/jsvalid.icn and ipl/io.icn, ipl/random.icn, ipl/strings.icn, ipl/getpaths.icn, ipl/fullimag.icn are hand-semicoloned copies of /home/resources/unicon/ipl/procs (the Unicon versions, which differ from the Arizona IPL); import json is served by ../unicon_tests/uni_lib/json.icn through the ipath line there (identical to /home/resources/unicon/uni/lib/json.icn once semicolons are ignored). Each file's text equals the upstream file with the semicolons and white space ignored (checked line by line), and a driver over io, strings, random, getpaths, fullimag and the json validator printed the same under unicon on the originals and under SCRIP on the copies. KNOWN SCRIP DEFECT, not a conversion fault: stat() called only inside a linked file fails in the Unicon dialect (exists() and isabspath() of ipl/io.icn fail) unless the main program also names stat; so a run of jsvalid that reaches its exists() calls is wrong until that is cured (the graded usage run never reaches them).
THE PARSER SMALL CLASSES (the coo, row unicon-uni-closure-parser-small-classes, 2026-11-13 16:4x CST; part of the ulsp/launch-lsp and unidoc/UniDoc closure): parser/parsedprocedure.icn parsedmethod.icn parsedrecord.icn parsedfunction.icn databaseinfo.icn parsedinitiallymethod.icn are hand-semicoloned copies of /home/resources/unicon/uni/parser (70 semicolons, each a line end where unilex.icn inserts one, plus the one SCRIP wants before every end); unigram.prefix.icn, unigram.suffix.icn and ytab_h.icn are byte-identical copies (declarations and $define lines only). Each copy differs from its original only by added semicolons, the unicon translator gives each the same ucode as its original once the line, colm, synt, filen and uid records and link folders are set aside, and scrip --dump-ast --dialect=unicon reads each.
