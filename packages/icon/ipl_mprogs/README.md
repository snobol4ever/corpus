# ipl_mprogs -- the event monitors of the Icon program library

Nine MT-Icon monitors of Arizona Icon 9.4.3's ipl/mprogs (piano from unicon-git's ipl/mprogs), each graded on the screen road over one target, `target.icn`
(staged as `NAME.fixtures/target.icn`, built beside the monitor into the icode its ALL.args line names). Step M1 of the cto's design (skill icon reference
section 9, THE EVENT MONITORS; row icon-mprogs-step-m1-the-nine-monitors-stand-in-a-container-cut-on-the-monitoring-oracle, officer_04 2026-11-16).

- THE ORACLE is Arizona Icon 9.4.3 built with EventMon and X Windows, `/home/resources/icon-943-mt` (build_v943mt.sh and ORACLE.md in
  /home/resources/progress/icon-graphics-2026-11-16/mprogs; two builds byte equal), the last Arizona release with multiple programs and the monitors.
  The one prover, prove_ipl_gprogs_entry.py, uses it for this package alone, its IPATH that build's lib and its LPATH its own ipl includes.
- THE TEXT is the semicolon form of util_icon_semicolons.py; the 9.4.3 translator makes the same ucode from it as from the original, each of the nine.
- THE ANSWERS: each `NAME.out` is the screen line of the monitor's still picture, cut twice equal by the prover's own staging (the same md5 officer_01's
  census read). Every monitor is named in EVENTS-NONE.tsv: none reads a key or the mouse, so the road ends each at its still picture.
- eve is NOT-CUT.tsv's: it builds on no oracle (vstopsgn is in no tree; its EvSend is Unicon's).
- On SCRIP every entry reads red by design until the monitoring steps M2 to M6 land: SCRIP has no EvGet and loads no second program.
